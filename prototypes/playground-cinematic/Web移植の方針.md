# Web移植の方針

第4次ではBlenderのCyclesで理想の状態を作りました。そのままではブラウザで動かないものがいくつかあります。この文書は、何がそのまま持っていけて、何を作り直す必要があるかを整理したものです。Three.jsにはまだ統合していません。

## そのまま持っていけるもの

- **分け方**：モデルは `arch.py`・`furniture.py`・`details.py`、素材は `scene.py`、光と空と時間帯は `look.py` に分けてあります。Webでも「モデルはGLB、光と空はThree.js」という第3次と同じ分担にできます。
- **名前**：画面は `Screen_<端末>`、端末の親は `Terminal_<端末>`、カメラは `Cam_<名前>` です。Three.js側は名前でそれぞれを見つけられます。
- **形の定義**：殻と床は数式（`arch.py` の `dome()` と `floor_height()`）で決まります。解像度を変えて作り直せるので、Web用の軽いメッシュも同じ式から出せます。
- **発光の調光**：照明の素材には `emit_base` と `emit_always` を持たせ、時間帯ごとに1つの係数で明るさを変えています。Webでも同じ係数で調光できます。

## 作り直しが必要なもの

### 1. ポリゴン数

現在は約146万ポリゴンで、第3次（約15.7万）の約9倍です。内訳の8割は次の2つです。

| 部位 | 現状 | Web用の方針 |
|---|---|---|
| 床（高さを数式で決めた面） | 5cm格子で約32万です。 | 同じ式から、平らな部分は粗く、段差の部分だけ細かい格子で作り直します。目標は3万以下です。 |
| 端末と家具の一体成形 | ボクセルで融合したため、9体で約86万（1体あたり平均約10万）です。 | 簡略化したメッシュを作り、元の高精細メッシュから法線マップを焼きます。目標は1体1万前後です。 |

殻（7.2万）、カーテン（2.6万）、植物（1.8万）は、分割数を減らすだけで済みます。窓の外の雲（約8万）はWebでは画像に置き換えるので数えません。全体の目標は20万ポリゴン以下です。

### 2. 間接光

第4次の質感は、Cyclesの間接光（光が殻の内側で何度も跳ね返ること）に支えられています。Three.jsの標準の光では、これが出ません。第3次が硬く見えた主な原因もここにあります。

- 動かないもの（殻、床、作り付けの家具）には、**時間帯ごとのライトマップ**を焼きます。朝・昼・夕方・夜の4組（1組は2面）を用意し、時刻に応じて前後の2組を混ぜます。こうすれば、太陽の影や照り返しを焼いても、時間帯の連続変化は保てます。
- 景色（空・雲・水面）による室内の色の変化は、ライトマップ全体に色を掛けて近似します。景色ごとに焼くと枚数が3倍になるためです。
- 小物や植物のように細かいものは、時間帯ごとの環境光（第3次で使った仕組み）で照らします。
- 朝と昼は、Blenderで白の基準を寒色に寄せています（`look.py` の `wb`）。ライトマップと空の画像にはこの補正が入らないので、Three.jsの最後の色調整で同じ補正を掛けます。こうすると、時刻に応じて補正の強さも連続的に変えられます。端末に近づいたときは、Blenderのクローズアップ（`look.py` の `wb_close`）と同じように補正を弱めます。
- ライトマップはWebPで持ちます。KTX2は展開にWebAssemblyが必要で、本番PortalのCSP（`script-src 'self'`）のままでは動きません。

### 3. 空と雲

Cyclesのボリューム雲は1枚の描画に1〜2分かかるため、リアルタイムには描けません。

- **推奨**：景色3種×時間帯4種の空を、Blenderから全天の画像として書き出します。雲だけを動かせるように、雲のない空と、透明度つきの雲の層を別々に書き出します（12組、24枚）。Three.jsでは時刻に応じて前後の2組を混ぜ、雲の層だけをゆっくり横へ流します。室内の環境光にも同じ画像を使えるので、空と室内の色が必ず合います。
- **代案**：第3次の手続き型の空（シェーダーで雲を描く方式）を使い続けます。時間変化は滑らかですが、雲の立体感はBlenderの画に届きません。
- 夜の星と月は、どちらの方式でもシェーダーで足します。

### 4. 床と水の反射

- 床は「つや消しに近い磨き」に変えました。第3次の鏡のような反射ではなく、ぼけた反射が必要なため、低解像度で描いた反射をぼかして重ねます。
- 室内の水盤には鏡に近い反射が必要です。面積が小さいので、水盤の範囲だけ別に反射を描きます。
- 屋外の水面は波の法線で空を映します。第3次のシェーダーをそのまま使えます。

### 5. 素材

| Blenderの素材 | Webでの再現 |
|---|---|
| 殻の漆喰（細かい凹凸） | 繰り返しの法線テクスチャを1枚使います。 |
| 床のテラゾー（つやのむら） | 粗さのテクスチャを1枚焼きます。 |
| セラミック（クリアコート） | `MeshPhysicalMaterial` のクリアコートを使います。 |
| アルマイト（作品の色） | 第3次と同じく、金属の色を作品のサムネイルから設定します。 |
| ガラス（建築用の薄いガラス） | 専用シェーダーを使います。曇るギミックもここに入れます。 |
| ボイルのカーテン（透ける布） | 半透明かつ逆光で明るくなる専用シェーダーを使います。揺れは頂点シェーダーで表現します。 |
| ブークレとウール | 法線テクスチャと布の光沢（sheen）を組み合わせて使います。 |
| 画面 | 第3次と同じく、HTMLを画面の矩形に重ねます。 |

### 6. 被写界深度と露出

クローズアップで使った背景のぼけ（被写界深度）は、後処理で入れられますが負荷が高いので、端末に近づいたときだけ有効にします。露出は第3次と同じく時間帯ごとの値を補間します。

「空だけをカメラから少し暗く見せる」処理（`look.py` の `SKY_SEEN`）は、Webでは空を描くシェーダーの明るさを下げるだけで再現できます。

## スマホ版

第3次と同じく、部屋のデータは読み込みません。壁紙には、上の「空と雲」で書き出した全天画像の一部を使います。これでPC版と同じ空を、ほとんど負荷なしで見せられます。

## 進める順番

1. 全天の空と雲の画像12組をBlenderから書き出し、Three.jsで時刻に応じて混ぜます。ここで空の印象が保てるかを先に確かめます。
2. 殻と床をWeb用の解像度で作り直し、4つの時間帯のライトマップを焼きます。
3. 端末と家具を簡略化して法線マップを焼きます。
4. 第3次の試作（`prototypes/playground-3d`）のカメラ・画面・操作の仕組みはそのまま使い、モデルを新しいGLBに差し替えます。
5. 画質の段階（高画質と軽量）を用意し、低スペック機で動くことを確かめます。

## 見込んでいる容量

| 種類 | 見込み |
|---|---|
| GLB（頂点の量子化なし） | 6〜8MB |
| ライトマップ（2048×2048を2面×4時間帯、WebP） | 3〜5MB |
| 全天の空と雲の層（2048×1024を24枚、WebP） | 5〜7MB |
| 法線・粗さのテクスチャ | 2MB前後 |

第3次（GLB 5.5MB＋AO 0.7MB）の2〜3倍になります。初回表示では、いまの時間帯に当たるライトマップ1組と空の画像1組だけを読み込み、残りは裏で読み込む構成にします。

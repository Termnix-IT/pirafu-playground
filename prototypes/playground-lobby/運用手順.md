# ロビー試作の運用手順

`prototypes/playground-lobby` は、3D空間を背景にしたロビー画面の試作です。本番のPortal（リポジトリ直下の `src/`）からは読み込まれません。この文書には、トピックの管理、3Dアセットの作り直し、検証の手順をまとめています。特に断りのないかぎり、コマンドは `prototypes/playground-lobby` で実行します。

## 起動

1. リポジトリ直下で `npm ci` を済ませます（Vite、欧文フォントのSora、sharp、Playwrightは直下のものを使います）。
2. このフォルダで `npm install` を実行します（three.js、日本語フォントのM PLUS 2、GLBを加工する `@gltf-transform` が入ります）。
3. 3D空間のGLBは `prototypes/playground-3d` で作ります。まだ無い場合は、そのフォルダにある `制作手順.md` の手順2〜4を先に実行します。GLBが無くても、ロビーは静止画か空だけの表示で動きます。
4. `npm run dev` で開発サーバーを起動し、http://127.0.0.1:5175/ を開きます。起動のたびに `scripts/prepare-lobby.mjs` が走り、作品・トピック・更新情報を `public/assets/` に書き出します。

`public/assets/`、`verification/`、`dist/` は生成物で、Gitでは管理していません。

## 最新トピックの管理

ロビー左上の「最新トピック」は、`topics/` のファイルから作ります。トピックを足すときに、画面のコードを変える必要はありません。

- `topics/<id>.json`：トピック1件の記録です。形式は `topics/topic.schema.json` で決めています。
- `topics/banners/<id>.webp`：バナー画像です（拡張子は画像の形式に合わせます。`banner.path` に書いたパスの画像が使われます）。比率は21:9、幅は1260px以上にします（例：1260×540）。形式はWebP・PNG・JPEG・AVIFのどれでも構いません。

### 項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `schemaVersion` | ○ | `1` を書きます。 |
| `id` | ○ | 英小文字・数字・ハイフンを使った一意な名前です。ファイル名と同じにします。 |
| `kind` | ○ | 種別です。`game`（ゲーム）、`tool`（ツール）、`update`（アップデート）、`in-development`（開発中）、`video`（映像）、`article`（記事）、`making`（制作）、`notice`（お知らせ）から選びます。画面には出ず、読み上げで題名の前に付きます。 |
| `title` | ○ | 題名です。読み上げと、位置を示す印の説明に使います。 |
| `banner.path` | ○ | `topics/` から見た画像のパスです（`banners/…`）。 |
| `banner.alt` | ○ | 画像の代替テキストです。バナーに書かれている文字と、絵の内容を書きます。 |
| `link` | ○ | 行き先です。作品なら `{ "work": "<作品ID>" }`、ロビー内のページなら `{ "route": "updates" }`（`games`・`tools`・`lab`・`media`・`profile`・`updates` のどれか）、外部のページなら `{ "url": "https://…" }` のどれか1つを書きます。 |
| `from` | | 掲載を始める日時です。省くと、すぐに掲載します。 |
| `until` | | 掲載を終える日時です。省くと、終わりを決めずに掲載します。 |
| `order` | | 並び順です。数値が小さいほど先に出ます。省くと100になります。 |
| `enabled` | | `false` にすると、記録を残したまま掲載を止めます。 |

作品を指すトピックは、行き先として作品IDだけを持ちます。作品の説明や起動先をトピック側に写さないので、作品の情報を直しても食い違いません（`title` はバナーの読み上げに使う題名で、作品の題名と同じでなくても構いません）。非掲載の作品を指すトピックは、ビルドのときにエラーになります。

### 日時の書き方

`from` と `until` は、`2026-12-01T00:00:00+09:00` のように、UTCとの時差まで書きます。時差が無い書き方は受け付けません。こう書いておけば、どの地域で見ても同じ瞬間を指します。掲載するかどうかは、見ている人の端末の時計がその瞬間を過ぎたかどうかで決めます。ページを開いたままでも、1分ごとに見直します。

ビルドの時点ですでに掲載が終わっているトピックと、`enabled` が `false` のトピックは、配信物に入りません。

### 登録・変更・掲載終了

コマンドを使うと、入力の手間と書き間違いを減らせます。同じことは、エディタでJSONを直接編集してもできます。

```powershell
# 一覧と、いま掲載中かどうか
node scripts/topics.mjs list

# 登録（記録の雛形を作る。行き先は --work、--route、--url のどれか1つ）
node scripts/topics.mjs new winter-update --kind update --title "DOPASWEEPERに冬のステージ" --work dopasweeper --from 2026-12-20T00:00:00+09:00

# バナーを topics/banners/winter-update.webp に置いてから、検査する
node scripts/topics.mjs check

# いまから掲載を終える（日時を決めて終えるときは --at を付ける）
node scripts/topics.mjs end winter-update

# 記録を残したまま止める／戻す
node scripts/topics.mjs disable winter-update
node scripts/topics.mjs enable winter-update
```

題名・並び順・行き先を変えるときは、`topics/<id>.json` を直接編集して `check` を実行します。変更は、次の `npm run dev` か `npm run build` で画面に反映されます。

### バナーの作り方

バナーは、どの道具で作っても構いません。配色や文字組みは、トピックごとに自由に決めます。ロビーがそろえるのは、外形（21:9、右下の角の切り欠き）と操作だけです。

いまあるバナーは `topics/studio/` のHTMLとCSSで組み、撮影して画像にしています。同じ方法で作る場合は、`topics/studio/index.html` に `.banner` を1つ足し、開発サーバーを起動した状態で次を実行します。足した `.banner` の `id` 属性がファイル名になります。

```powershell
node scripts/render-banners.mjs --only winter-update
```

## 3Dアセットの最適化と作り直し

制作元のデータ（Blenderのスクリプトと、それが書き出すGLB）は `prototypes/playground-3d` にあり、ロビーはそれを書き換えません。ロビーが配信するのは、そこから作った軽いコピーです。

| ファイル | 作るスクリプト | 内容 |
|---|---|---|
| `public/assets/space.glb` | `scripts/optimize-space.mjs` | 配信用のGLBです。頂点を小さい整数で持たせ（`KHR_mesh_quantization`）、重複したデータをまとめ、使っていないUVを落としています。木目のテクスチャは `wood_ash.webp` として別のファイルに出します。GLBに埋め込んだままだと `blob:` のURLで読まれ、本番のPortalのCSPに止められるためです。 |
| `public/assets/ao_*.webp` | `scripts/prepare-lobby.mjs` | 第3次（`prototypes/playground-3d`）が焼いたAOを、そのまま写したものです。 |
| `public/assets/stills/*.webp` | `scripts/render-stills.mjs` | 部屋の静止画です。時間帯4種×景色3種の12枚と、その縮小版があります。 |

`space.glb` は、`npm run dev` と `npm run build` のたびに、元のGLBのほうが新しいときだけ作り直します。手で作り直すときは次を実行します。

```powershell
node scripts/optimize-space.mjs
```

DracoとMeshoptの圧縮は使っていません。どちらも読み込み側でWebAssemblyが必要になり、本番のPortalのCSP（`script-src 'self'`）では動かないためです。

カーテン・床・端末の画面の3種類は、量子化の対象から外しています。カーテンの揺れや、端末へ近づくカメラを計算するときに、これらのメッシュの元の寸法を使っているためです（`src/space/room.js`）。床は頂点が4つしかなく、量子化しても小さくならないので、そのままにしています。

### 静止画

静止画は、ロビーのカメラからthree.jsの画面をそのまま撮ったものです。3Dの読み込み中や、画質を「静止画」にしたとき、3Dを表示できない端末で開いたとき、3Dの読み込みに失敗したときに、背景として出します。

部屋の形・素材・光・カメラの位置のどれかを変えたら、撮り直します。開発サーバーを起動した状態で次を実行します（12枚で2〜3分かかります）。

```powershell
node scripts/render-stills.mjs
npm run assets
```

2行目の `npm run assets` は、どの静止画があるかの一覧をロビーのデータ（`public/assets/lobby.json`）に書き直します。ロビーは、一覧にある静止画だけを読みに行きます。

静止画は、画面に出る範囲より広く撮っています（`src/view.js` の `STILL`）。広く撮った絵の中央を切り出すと、同じ場所から狭い画角で撮った絵と同じになるので、1枚で16:10から21:9までの画面に合わせられます。これより縦長の画面では、静止画を画面いっぱいに広げて表示します。この場合、3Dに切り替わるときに構図が少し変わります。

## 画質の段階

設定の「画質」は次の5つです。値は `src/stage.js` の `LEVELS` と `src/space/room.js` の `QUALITY` にあります。

| 設定 | 描く画素数の上限 | アンチエイリアス | 光のにじみ | 床の映り込み | 影 | ガラスの屈折 | 1秒あたりの描画（動作中／静止中） |
|---|---|---|---|---|---|---|---|
| 高品質 | 260万 | 4倍 | あり | 画面の50% | 4096 | あり | 60／30 |
| 標準 | 180万 | 4倍 | あり | 画面の40% | 2048 | あり | 60／30 |
| 軽量 | 110万 | なし | なし | 画面の30% | 1024 | なし | 30／24 |
| 静止画 | 3Dを描きません。 | | | | | | |
| 自動 | 高品質から始めます。カメラや画面が動いていて、1秒あたり60回の描画を求めている間に、遅い描画が1秒ほど続いたら、1段下げます（軽量まで）。自動では上げ直しません。 | | | | | | |

描く画素数の上限は3D背景だけにかかります。Web UIの文字や札は、いつも画面の解像度で描きます。

画質が「静止画」のときは、three.jsと3Dアセットを読み込みません。画面がスマートフォンの幅のときは、部屋のGLBを読み込みません。

## 状態の保存先

| 保存先 | 保つもの |
|---|---|
| URL（共有できる） | 開いている区画と作品（`#/tools/poseref` など） |
| localStorage（次回も残る） | 景色、時間帯、表示モード、画質、UIの背景、動き |
| sessionStorage（このタブの間は残る） | 表示中のトピック、自動切り替えを止めたかどうか、自動の画質が落ち着いた段階 |
| メモリ（このページの間は残る） | カメラ、読み込んだ3D空間、UIを隠しているかどうか |

作品は別のタブで開くので、ロビーのタブに戻ったときに3D空間を読み込み直すことはありません。タブが隠れている間は描画を止めます。

## 検証と計測

`contact-sheets.mjs` 以外は、開発サーバー（`npm run dev`、port 5175）を起動した状態か、本番ビルドを配信した状態（`npm run build` のあと `npm run preview`、port 5176）で実行します。読み込み時間は、本番ビルドのほうで測ります。

| スクリプト | 内容 |
|---|---|
| `node scripts/check.mjs` | 操作を自動で確かめます（キーボード、カルーセル、設定、UIを隠す操作、3D端末、スマートフォン）。 |
| `node scripts/capture.mjs` | 時間帯・画面サイズごとの画面を撮影し、`verification/` に保存します。 |
| `node scripts/contact-sheets.mjs` | 撮影した画面を一覧画像にまとめます。 |
| `node scripts/measure.mjs --url http://127.0.0.1:5176/` | 読み込み時間と描画の負荷を測ります。初回（キャッシュなし）と再訪を分けて、3回ずつ測ります。この計測では、再訪でもシェーダーのコンパイル結果が残りません（ヘッドレスのChromeが保存しないため）。再訪の値は、ファイルのキャッシュだけが効いた状態のものです。 |

計測と撮影はGPUを使います。実行中にソースを編集すると、再読み込みが入って失敗します。ブラウザでロビーを開いたままにしていると、GPUを取り合って数値が悪くなります。

# Pirafu2411 Playground 空間試作（第3次）の制作手順

この試作は、Pirafu2411 Playground の3D空間を本番サイトから切り離して確かめるためのものです。Blenderで建築・家具・端末を作り、Three.jsで光・空・時間帯の変化・操作を付けています。本番のPortal（リポジトリ直下の `src/`）からは読み込まれません。

## 役割の分け方

Blenderは形と素材だけを受け持ち、時間で変わるものはすべてThree.jsが受け持ちます。太陽の光と影をテクスチャに焼くと朝・昼・夕方・夜の連続変化ができなくなるので、焼いているのは時刻に依存しないアンビエントオクルージョン（AO。物が接する隅にできる淡い陰）だけです。

| 担当 | 内容 |
|---|---|
| Blender（`blender/`） | モデリング、マテリアルの基本値、木目テクスチャの生成、AO用のUV展開とベイク、GLBの書き出し |
| Three.js（`src/`） | 時刻に応じた太陽・空の色・露出、影、空と雲と水面の描画、床の反射、ガラスの屈折、端末の画面、カメラ、ポストプロセス、画質の切り替え |

## フォルダ構成

```
prototypes/playground-3d/
├─ blender/
│  ├─ lib.py              形を作る関数（押し出し、回転体、スイープ、面取りなど）
│  ├─ build_scene.py      全アセットを生成して build/playground.blend に保存する
│  ├─ bake_export.py      オブジェクトを結合してAO用のUVを展開し、AOをベイクしてGLBを書き出す
│  ├─ render_preview.py   Blender上で確認用にレンダリングする
│  └─ build/              生成物（.blend、レンダリング画像）
├─ scripts/
│  ├─ prepare-works.mjs   カタログから端末に出す作品情報とサムネイルを作る。AOをWebPに変換する
│  └─ capture.mjs         時間帯と景色ごとの検証画像を自動で撮る
├─ src/
│  ├─ main.js             UI、カメラ、時刻、描画ループ
│  ├─ sky.js              空・雲・水面のシェーダーと、時間帯の配色
│  ├─ room.js             GLBの読み込み、マテリアルの調整、光、床の反射（PC版だけが読み込む）
│  └─ style.css
├─ public/assets/         生成物（GLB、AO、作品情報）
└─ verification/          生成物（検証画像）
```

`blender/build/`、`public/assets/`、`verification/`、`dist/` はスクリプトから作り直せるので、`.gitignore` で管理対象から外しています。

## 必要なもの

- Blender 5.2（5.2.2 LTSで確認）。`blender.exe` をコマンドラインから実行します。
- Node.js 24。Vite、sharp、フォント、Playwrightはリポジトリ直下の `node_modules` を使うので、先に直下で `npm ci` を済ませます。
- 検証画像を撮るには、Chrome・Edge・Playwright用Chromiumのいずれかが必要です。

## 作り直す手順

すべて `prototypes/playground-3d` で実行します。Blenderのパスは環境に合わせて読み替えてください。

1. Three.jsを入れます（初回だけ）。

   ```powershell
   npm install
   ```

2. アセットを生成します。約15秒で `blender/build/playground.blend` ができます。

   ```powershell
   & "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python blender\build_scene.py
   ```

3. AOを焼いてGLBを書き出します。GPU（OptiXまたはCUDA）で約5分かかります。`public/assets/playground.glb` と3枚のAO画像（PNG）ができます。

   ```powershell
   & "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python blender\bake_export.py
   ```

4. 作品情報とサムネイルを作り、AO画像をWebPに変換します。

   ```powershell
   node scripts/prepare-works.mjs
   ```

5. 開発サーバーを起動して http://127.0.0.1:5174/ を開きます。

   ```powershell
   npm run dev
   ```

形だけを確かめたいときは、手順2のあとにBlender上でレンダリングできます。画像は `blender/build/renders/` に保存されます。

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python blender\render_preview.py -- --engine cycles --views wide,game,tool,experiment,media --time noon
```

## アセットの構成

`build_scene.py` は約270個のオブジェクトを作り、それぞれに `grp`（書き出すときにどのメッシュへまとめるか）というカスタムプロパティを付けます。`bake_export.py` はこの値ごとにオブジェクトを結合するので、GLBのメッシュは次の16個になります。合計は約15.7万ポリゴンです。

| メッシュ | 内容 | ポリゴン | AO |
|---|---|---:|---|
| `Structure` | リブ、母屋、妻壁の方立、扉枠、光の輪の筐体、床スラブ | 27,100 | なし |
| `Interior` | 腰壁、中央の段、アーチのある壁、デイベッド、サイドテーブル、照明の台、鉢 | 16,588 | `ao_room` |
| `Terminal_game` ほか3つ | 端末ごとの机、筐体、スタンド、キーボード、案内プレート、小物 | 10,896〜13,812 | `ao_terms` |
| `Screen_game` ほか3つ | 端末の画面。Three.jsが作品画像を描いたテクスチャに差し替える | 各26 | なし |
| `GlassSolid` | 厚みのあるガラス（机の脚、筐体の背面、球、フラスコ、ガラスの本） | 13,654 | なし |
| `VaultGlass` | ヴォールトと妻壁の板ガラス | 1,232 | なし |
| `Plants` | 蔓、オリーブの木、プランターの草 | 25,652 | なし |
| `Curtain` | カーテン。揺れはThree.jsの頂点シェーダーで付ける | 21,600 | なし |
| `Emitters` | 光るもの（光の輪、電球、端末内部の光、LED） | 3,276 | なし |
| `Floor` | 床。反射・目地・AOはThree.jsのシェーダーで描く | 2 | `ao_floor` |

`Light_ring`、`Light_orb0` などの空のノードは、Three.jsが点光源を置く位置を示します。

### 座標

Blenderでは X が右、Y が奥、Z が上です。GLBではThree.jsの座標（x, z, -y）に変換されます。視点はBlender座標で (1.2, -9.0, 1.6) 付近から奥を見ています。

### マテリアルの名前

Three.jsは、マテリアルの名前を手がかりに仕上げを変えています。名前を変えるときは `src/room.js` も直します。

| 名前 | 素材 | Three.js側の扱い |
|---|---|---|
| `WhiteSteel` | 白い塗装の金属 | 構造体ではクリアコートを外す |
| `Plaster` | 壁・腰壁・段の左官仕上げ | そのまま |
| `Ceramic` | 端末の筐体 | そのまま（クリアコートあり） |
| `Aluminum`、`Champagne` | 金属 | そのまま |
| `Wood` | 木。木目には `build_scene.py` が生成したテクスチャを使う | そのまま |
| `GlassClear`、`GlassFrost`、`BookGlass*`、`GlassTint_<端末>` | ガラス | 厚み・色の減衰を設定する。`GlassTint_*` は作品の色に染める |
| `GlassVault` | 板ガラス | 専用シェーダーに差し替える（浅い角度でだけ空を映す） |
| `Screen_<端末>` | 画面 | 作品画像を描いたテクスチャに差し替える |
| `Core_<端末>`、`Accent_<端末>` | 端末内部の光、アクセントのキー | 作品のサムネイルから取った色を入れる |
| `EmitCool`、`EmitWarm` | 照明 | 時間帯で明るさを変える |
| `Curtain` | 布 | 半透明にして、揺れを付ける |

端末の色は `scripts/prepare-works.mjs` がカタログのサムネイルから取り出し、`public/assets/works.json` に書きます。作品を差し替えてもBlender側を作り直す必要はありません。

### AO

- `Interior` と `Terminal_*` は2つ目のUV（`AO`）にAOを焼いています。1つ目のUV（`UVMap`）は木目用です。
- 床は1つ目のUVに焼いています。Three.js側は床の位置から直接AOを参照するので、床の範囲を変えたら `src/room.js` の `FLOOR` も直します。
- AOは環境光にだけ掛かります。太陽の影はThree.jsのシャドウマップが描きます。
- 光を遮らない扱いにするため、板ガラスとカーテンはAOを焼くときだけ隠しています。

### 書き出しの設定

書き出しの設定は `bake_export.py` の末尾で指定しています。形式はGLB、座標はY軸上、画像はWebP（品質82）で、UVと法線を含め、カメラ・ライト・アニメーションは含めません。DracoとMeshoptの圧縮は使っていません。どちらも読み込み側でWebAssemblyの展開処理が必要になり、本番PortalのCSP（`script-src 'self'`）のままでは動かないためです。

## Three.js側の仕組み

- **時間帯**：`src/sky.js` の `KEYS` に、時刻ごとの空の色・太陽の強さ・露出を置いています。設定した時刻の間は連続的に補間します。
- **環境光**：その時刻の空を小さなキューブマップに描き、PMREMで環境マップにしています。下半分は「明るい床からの照り返し」に置き換えています。これがないと、日陰の白が空の青に沈みます。
- **床の反射**：上下を反転したカメラで部屋を描き、床のシェーダーで重ねています。
- **ポストプロセス**：4倍MSAA、控えめなブルーム（しきい値0.97）、Neutralトーンマッピングを使っています。
- **スマホ版**：`room.js` を読み込まないので、GLBもAOもダウンロードしません。空のシェーダーだけが動きます。

### 負荷を抑えている点

- 影は、太陽が動いたときだけ描き直します。
- 床の反射は、カメラが動いている間は毎フレーム、止まっている間は1フレームおきに描きます。
- ガラスの屈折に使う画像は、半分の解像度で描きます。
- 点光源は光の輪と大きな球の2つだけで、昼は消します。ほかの照明は電球の発光とブルームで見せています。
- 画面の画素数に上限を設け、大きな画面や高精細な画面でも描く画素が増えすぎないようにしています。
- 最初の数秒で1フレームの描画が30ミリ秒を超えた場合は、自動で画質を「軽量」に落とします（MSAA・ブルーム・屈折は使わず、影の解像度は2048にします）。

## 検証画像の撮り方

開発サーバーを起動した状態で次のコマンドを実行すると、`verification/` に時間帯（朝・昼・夕方・夜）と景色（空・雲・水面）の組み合わせ、端末に近づいた画面、スマホ版の画像を保存します。あわせて各画面のfpsも表示します。

```powershell
node scripts/capture.mjs
```

## 既知の制約

- GLBは約5.5MB（gzipで約2.5MB）です。頂点を量子化すれば容量を減らせる見込みですが、まだ量子化していません。
- 植物はポリゴンの葉を並べたもので、風には揺れません。
- 雲は方位と仰角の平面上で作った擬似的な立体で、本物のボリュームではありません。
- 端末の振り分け（GAME・TOOL・EXPERIMENT・MEDIA）は `scripts/prepare-works.mjs` に直接書いています。Portalのデータ契約には、まだこの分類がありません。
